# Backlog #45: A rescue for a drone whose estimate is NaN

The row's history, moved from the [decision backlog](../decision-backlog.md) on 2026-11-16. The row keeps the open question.

**A rescue for a drone whose estimate is NaN** ([ADR-0045](../decisions/0045-rescue-without-an-estimate-points-to-the-emergency-stop.md)). Today the rescue landing sends the operator to the emergency stop. The same holds in flight: when the estimate turns NaN after `connect()`, the safety pre-check fails on the stale values, but the failsafe's landing is a position command too, so the drone can't follow it (found in a review, 2026-11-04). Candidates (a) and (b) are from Joe's question, 2026-11-03: (a) reset the estimator in flight (`kalman.resetEstimation`), let the Flow deck rebuild it, then land normally (ADR-0038 already has the in-flight reset as a VERIFY; [ADR-0054](../decisions/0054-a-fresh-estimate-for-every-take-off.md) found that a reset also sets the height estimate to 0 and the attitude estimate level, `kalman_core.c` 158-213 at 2026.08, and forbids resets in flight, so (a) would need a new ADR); (b) a descent on tilt and thrust (cflib's `send_setpoint(roll, pitch, yaw_rate, thrust)`: the drone's lean and motor power are commanded directly, like throttle and steering on a vehicle instead of a destination), level and a little below hover thrust (the motor power that just holds the drone up), with touchdown from the raw down range (`range.zrange`, the sensor's own reading, which doesn't go through the estimator). Check first, in the firmware: does attitude survive a NaN position in the Kalman filter (one state, one covariance matrix)? If not, nothing can fly it. (b) also needs hover thrust (it changes with battery charge), accepts sideways drift, and adds a new kind of command (a drone interface decision). (c) A manual descent in cfclient (Joe's idea, 2026-11-04): the operator flies the drone down with a gamepad in cfclient's manual mode, which commands lean and thrust like (b), before falling back to the emergency stop. The same attitude check decides it. Also check at the Bench, with propellers off: does connecting cfclient send zero thrust at once (it streams the gamepad's setpoints, and its thrust lock wants the stick at zero), which would drop the drone? The rescue landing has to exit first, since one Crazyradio serves one program; cfclient's assist modes (altitude hold, position hold) use the estimate, so only full manual mode applies; and it needs practice in cfclient first. If (c) holds, a new ADR changes ADR-0045's message to point to it first.
